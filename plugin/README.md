# Scrapalot AI Toolkit

The Claude Code tooling that runs the [Scrapalot](https://scrapalot.app) AI stack:
per-book corpus audits, RAG answer grading, an autonomous DevOps fix loop,
competitive research turned into shipped features, and the per-stack code-quality
passes for the Python AI backend, the Kotlin backend and the React frontend.

## Install

```bash
claude plugin marketplace add https://api.scrapalot.app/marketplace.json
claude plugin install scrapalot@scrapalot
```

Update later with `claude plugin update scrapalot`.

Everything lands under one namespace, so `/scrapalot:` in the prompt lists the
whole set: `/scrapalot:book`, `/scrapalot:rag-test`, `/scrapalot:devops-loop`,
and the rest. Agents appear in the @-mention typeahead as `scrapalot:rag-tester`,
`scrapalot:prd-builder` and so on.

| Skills | 14 | `humanize-ai`, `okf`, `langchain`, `pydantic-ai`, `tech-debt-analyzer` |

`.claude-plugin/marketplace.json` carries the full inventory with a description
for every entry; it is generated by `build-marketplace.py`, never hand-edited.

## What it expects

Most commands drive a running Scrapalot deployment — Docker containers named
`scrapalot-chat`, `scrapalot-backend`, `scrapalot-workers`, pgvector, Neo4j and
Redis — and they read and write that stack directly. Outside such a deployment
the corpus, RAG and DevOps commands have nothing to talk to. The writing,
research and code-quality skills (`humanize-ai`, `competitive-analysis`,
`tech-debt-analyzer`, `dead-code-finder`, `seo-optimizer`) stand on their own.

## Where state goes

Plugin files are replaced wholesale on every update, so nothing durable is
written inside the plugin. Run state lives in the project instead, under
`${CLAUDE_PROJECT_DIR}/.claude/`:

| Path | Written by |
|---|---|
| `gates/active/`, `gates/done/` | the gate ledger (`scripts/gate-check.py`) |
| `postprocess/progress.txt` | `/scrapalot:postprocess-parse`, `/scrapalot:postprocess-graph` |
| `rag-test/STATE.md` | `/scrapalot:rag-test` |
| `devops-loop/seen-errors.jsonl` | `/scrapalot:devops-loop` |
| `competitive-analysis/analyzed_*.txt` | `/scrapalot:competitive-analysis` |

`SCRAPALOT_GATES_DIR` overrides the ledger location; `SCRAPALOT_GATES_OFF=1`
disables the Stop hook.

## Hooks

All three are gated on a signal from the run they protect and are a silent
no-op otherwise, so an ordinary session never sees them:

- **`postprocess_guardrail.sh`** (PreToolUse/Bash) — warns when a command
  dispatches several document reprocess tasks at once, against the per-document
  sequential rule.
- **`devops_loop_guardrail.sh`** (PreToolUse/Bash) — only with
  `SCRAPALOT_DEVOPS_LOOP=1`; blocks pushes to `main`, force-pushes, PR merges and
  destructive container or database commands.
- **`gates_stop_guardrail.sh`** (Stop) — refuses to end a turn while a gate
  ledger still has unmet gates. Fails open on any error.

`hooks/pre-ui-change.sh` and `hooks/post-ui-change.sh` ship unwired; add them to
`settings.json` yourself if you want the frontend style checks.
